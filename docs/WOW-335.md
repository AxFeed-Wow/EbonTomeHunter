# Règles du client WoW 3.3.5a (build 12340) — ce qui marche, ce qui n'existe pas

Référence générale pour écrire du code qui tourne sur le client de Project Ebonhold. À relire avant toute modification : l'erreur la plus fréquente est d'utiliser une API *retail*.

Sources : FrameXML 3.3.5a (https://github.com/wowgaming/3.3.5-interface-files),
https://wowwiki-archive.fandom.com/wiki/Patch_3.3.5/API_changes,
https://wowpedia.fandom.com/wiki/World_of_Warcraft_API (⚠ Wowpedia documente surtout le
**retail** : vérifier la mention « Patch 3.x » ou l'usage dans FrameXML avant d'utiliser
une fonction), et les pièges documentés dans les addons Ebonhold (« EC-TRAP »).

**En cas de doute sur l'existence d'une fonction** : chercher son nom dans
`tools/api_globals_335.txt` (35 000 noms extraits du FrameXML 3.3.5a) et les évènements dans
`tools/api_events_335.txt`, ou dans un clone de `3.3.5-interface-files`. `python tools/check.py` le
vérifie pour tout le code.

## 1. Langage : Lua 5.1

| Interdit (5.2+) | À utiliser |
|---|---|
| `goto`, `::label::` | `repeat ... until true` + `break`, ou fonctions |
| `a // b` | `math.floor(a / b)` |
| `&`, `|`, `~`, `<<`, `>>` | `bit.band`, `bit.bor`, `bit.bxor`, `bit.lshift`, `bit.rshift`, `bit.bnot` |
| `table.unpack`, `table.pack` | `unpack`, `{ n = select("#", ...), ... }` |
| `utf8.*`, `string.pack`, `math.type`, `table.move` | n'existent pas |
| `load(string)` | `loadstring(str)` |
| `#` sur table à trous | compter avec `pairs` ; `{...}` + `unpack` tronque au 1er nil → utiliser `select("#", ...)` |

- **Maximum 200 variables `local` par fonction (y compris le chunk principal du fichier)** :
  au-delà, « too many local variables ». Regrouper dans des tables.
- Maximum 60 upvalues par fonction.
- `cond and nil or x` renvoie **toujours** `x` (nil est faux) : écrire un `if`.
- Une `local function` n'est visible **qu'après** sa déclaration : déclarer en avance
  (`local Foo` puis `function Foo() end`) toute fonction utilisée par une closure définie plus haut.
- `string.format("%d", x)` avec un flottant : arrondir avant (`math.floor(x + 0.5)`).
- Helpers WoW disponibles : `strsplit`, `strjoin`, `strtrim`, `strmatch`, `tinsert`,
  `tremove`, `wipe`, `tContains`, `format`, `floor`, `date`, `time`, `debugstack`,
  `hooksecurefunc`, `securecall`, `geterrorhandler`, `bit.*`.

## 2. Structure d'un addon

```
Interface/AddOns/MonAddon/
  MonAddon.toc          -- même nom que le dossier (obligatoire)
  Core.lua ...          -- listés dans le .toc, chargés dans l'ordre
  Bindings.xml          -- optionnel, chargé automatiquement (pas dans le .toc)
  Media/*.tga|*.blp     -- textures : TGA 32 bits ou BLP, dimensions en puissance de 2
```

```toc
## Interface: 30300
## Title: |cff66ccffMonAddon|r
## Notes: Une phrase.
## Author: Nom
## Version: 1.0.0
## SavedVariables: MonAddonDB
## SavedVariablesPerCharacter: MonAddonCharDB
## OptionalDeps: ProjectEbonhold

Locale.lua
Core.lua
```

- Chaque fichier reçoit `local addonName, ns = ...` (table de namespace partagée entre fichiers).
- Les SavedVariables valent **nil** jusqu'à `ADDON_LOADED` (arg1 == nom de l'addon) ; elles
  sont écrites à la déconnexion / `/reload`. N'y stocker que des données sérialisables
  (pas de frames ni de fonctions).
- **La sauvegarde REMPLACE la variable globale juste avant `ADDON_LOADED`** : une table créée au
  chargement du fichier (`MonDB = MonDB or {}; MonDB.x = MonDB.x or {}`) est perdue dès qu'une
  sauvegarde existe, et une référence gardée (`ns.DB = MonDB`) pointe sur la table jetée. Appliquer
  les valeurs par défaut sur `ADDON_LOADED` (`ns.InitDatabase` dans Core.lua ; le faux client le simule).
- Pas de `## IconTexture`, `## Category`, `## AddonCompartmentFunc` (retail).
- Encodage UTF-8 (sans BOM de préférence) pour les accents.
- Textures : chemin sans extension `"Interface\\AddOns\\MonAddon\\Media\\icon"`.

## 3. Séquence de chargement et évènements

1. Fichiers Lua exécutés (les SavedVariables ne sont PAS encore chargées).
2. `ADDON_LOADED` (arg1 = nom) → initialiser la DB avec des valeurs par défaut.
3. `VARIABLES_LOADED`.
4. `PLAYER_LOGIN` → données joueur disponibles (nom, classe), créer l'UI.
5. `PLAYER_ENTERING_WORLD` (à chaque écran de chargement) → attendre celui-ci avant les
   appels ProjectEbonhold par personnage.
6. `PLAYER_LOGOUT` → dernière chance d'écrire dans la DB.

Signature : `frame:SetScript("OnEvent", function(self, event, ...) end)`.
**Jamais** les globales implicites `this`, `event`, `arg1` (style 1.x).

`COMBAT_LOG_EVENT_UNFILTERED` en 3.3.5a — arguments passés **directement** :
```lua
function(self, event, timestamp, subEvent, srcGUID, srcName, srcFlags, dstGUID, dstName, dstFlags, ...)
-- SPELL_DAMAGE : ... = spellId, spellName, spellSchool, amount, overkill, school, resisted, blocked, absorbed, critical, glancing, crushing
-- SWING_DAMAGE : ... = amount, overkill, school, resisted, blocked, absorbed, critical, glancing, crushing
```
Pas de `hideCaster`, pas de `srcRaidFlags` (ajoutés en 4.x), pas de `CombatLogGetCurrentEventInfo`.
Transmettre `...` directement plutôt que `{...}` (trous nil).

`CHAT_MSG_ADDON` : `prefix, message, channel, sender`.
**`frame:RegisterEvent("NOM")` lève une erreur si l'évènement n'existe pas dans ce client**
(ex. `GET_ITEM_INFO_RECEIVED`, `QUEST_POI_UPDATE`) : `ns.RegisterEvent` l'enveloppe dans un `pcall`.
Carte du monde : le clic droit sur `WorldMapButton` dézoome, utiliser Ctrl + clic gauche pour une
action personnalisée ; ne jamais appeler `SetMapToCurrentZone()` pendant que `WorldMapFrame` est ouvert.
Carte affichée : `GetMapInfo()` renvoie son **nom de fichier** (`"Elwynn"`, `"Azeroth"` = continent des
Royaumes de l'Est, `"Expansion01"` = Outreterre), indépendant de la langue ; `GetCurrentMapAreaID()`
renvoie l'id WorldMapArea **+ 1** ; `SetMapByID(id)` prend l'id WorldMapArea (`reference/data/maps.json`, `MapData.lua`).
Point sur la carte : fraction 0..1 depuis le coin haut-gauche →
`pin:SetPoint("CENTER", WorldMapButton, "TOPLEFT", x * WorldMapButton:GetWidth(), -y * WorldMapButton:GetHeight())`
(y vers le bas, donc négatif). Passer d'une carte à l'autre par les coordonnées monde (bornes de
`maps.json`) : `x = (left - worldY) / (left - right)`, `y = (top - worldX) / (top - bottom)`.
Bois des Chants éternels, Terres Fantômes, Quel'Danas, Azuremyst, Brumesang (et Lune-d'argent,
l'Exodar) sont sur la carte **530** (bornes dans ses coordonnées) mais dessinés sur les cartes des
Royaumes de l'Est / Kalimdor (`shownOn` dans `maps.json`) : ne pas les comparer aux points des
cartes 0 / 1, ni les afficher sur la carte continentale d'Outreterre.
`UNIT_AURA`, `UNIT_HEALTH`… : `unit` en arg1 (pas de `RegisterUnitEvent` → filtrer soi-même).
`BAG_UPDATE` (bagId) se déclenche en rafale → **débouncer** (timer 0.2–0.5 s).

## 5. Sécurité, taint et combat

- **Fonctions protégées** (seulement via un clic du joueur sur un bouton sécurisé) :
  `CastSpellByName`, `CastSpellByID`, `UseAction`, `TargetUnit`, `AssistUnit`, `FocusUnit`,
  `RunMacroText`, `SpellStopCasting`, `UseItemByName`, `UseInventoryItem`, `CancelUnitBuff`,
  déplacements… → utiliser un `CreateFrame("Button", "Nom", parent, "SecureActionButtonTemplate")`
  avec `SetAttribute("type", "spell")`, `SetAttribute("spell", nom)` (ou `"macro"` / `"macrotext"`,
  `"item"`), **configuré hors combat**.
- **En combat** (`InCombatLockdown()`) : impossible de modifier `SetAttribute`, `Show/Hide`,
  `SetPoint` des frames sécurisées → différer à `PLAYER_REGEN_ENABLED`.
- Autorisé hors bouton sécurisé : `UseContainerItem` (vendre chez un marchand, ouvrir),
  `PickupContainerItem`, `DeleteCursorItem` (non protégé en 3.3.5a), `SelectGossipOption`,
  `BuyMerchantItem`, `RepairAllItems`, `SendChatMessage`, `CallCompanion` (peut échouer
  silencieusement pendant le GCD).
- **Ne jamais remplacer** une fonction Blizzard globale (`ContainerFrame_Update = ...`) :
  utiliser `hooksecurefunc("ContainerFrame_Update", fn)` (post-hook sans taint). Pour les
  scripts de frame : `frame:HookScript("OnShow", fn)`.
- Pas de presse-papiers : pour « copier », afficher une `EditBox` avec `:HighlightText()`.
- `StaticPopupDialogs["MONADDON_CONFIRM"] = { text=..., button1=YES, button2=NO, OnAccept=fn, timeout=0, whileDead=1, hideOnEscape=1 }`.

## 6. Communication

- `SendAddonMessage(prefix, msg, "PARTY"|"RAID"|"GUILD"|"BATTLEGROUND"|"WHISPER", target)`.
  `#prefix + #msg ≤ 254` octets, pas de `\t` dans le préfixe, pas de `\0`.
  Pas de canal « royaume » : utiliser un canal de discussion caché (voir `Net.lua`).
- Débit : ≤ ~8 messages/s (file d'attente avec délai 0.13–0.18 s) ; découper les gros
  messages en tranches numérotées ; limiter les réponses aux requêtes (≥ 30 s par joueur).
- Whisper vers un joueur hors ligne → message système « No player named … » : le filtrer.
- `SendChatMessage` ≤ 255 caractères.

## 7. Performance

- Pas de travail lourd dans `OnUpdate` : accumuler `elapsed` et agir toutes les N secondes.
- Cacher les résultats de `GetItemInfo` ; `GET_ITEM_INFO_RECEIVED` n'apparaît pas dans FrameXML 3.3.5a
  → ne pas en dépendre : réessayer plus tard (timer) quand `GetItemInfo` renvoie nil.
- Recycler les lignes des listes (FauxScrollFrame) plutôt que créer des centaines de frames.
  La ScrollFrame (**nommée** : ses enfants sont `$parentScrollBar`…) doit **recouvrir les lignes**
  (`TOPLEFT` et `BOTTOMRIGHT` de la liste) : la molette ne marche qu'au-dessus d'elle et sa barre se
  place à sa droite. Ancrée seulement au bord droit de la liste, elle a une largeur nulle : la molette
  ne fait rien et la liste semble limitée aux lignes visibles. Revenir en haut (`bar:SetValue(0)`) quand
  le filtre change, sinon l'ancien décalage peut pointer après la fin.
- FontString de largeur fixe sans hauteur : le texte trop long passe à la ligne et déborde sur la ligne
  suivante. Fixer aussi la hauteur (`fs:SetSize(200, 14)`) pour obtenir une troncature « ... ».
- Les frames ne peuvent pas être détruites : les créer une fois, les réutiliser.
- Scanner les infobulles avec un `GameTooltip` privé :
  `CreateFrame("GameTooltip", "MonAddonScanTip", nil, "GameTooltipTemplate")`,
  `tip:SetOwner(WorldFrame, "ANCHOR_NONE")`, lignes via `_G["MonAddonScanTipTextLeft"..i]`.

## 8. Localisation

`GetLocale()` → `"enUS"`, `"frFR"`, `"deDE"`, `"esES"`, `"ruRU"`… Table `L` avec repli
sur la clé (voir `Locale.lua`). Les textes renvoyés par le serveur (gossip Ebonhold, noms
d'Echoes) sont **en anglais** : comparer sur l'anglais, traduire seulement l'affichage.
