# Security Policy

**English** | [Français](#politique-de-sécurité)

## Supported versions

Security fixes go into the latest release of EbonTomeHunter. Please update before reporting a
problem.

## Reporting a vulnerability

Please do not report security vulnerabilities through public GitHub issues. Use
**Report a vulnerability** in the **Security** tab of the repository (GitHub private vulnerability
reporting).

Please include:

* a clear description of the problem;
* the steps to reproduce it (for example the exact message sent);
* its possible impact;
* the addon version.

Do not include passwords, account names or other personal data.

## What counts as a vulnerability

EbonTomeHunter receives messages from other players: drop places on a hidden chat channel, and
wishlists sent by addon message. For example:

* a message that triggers an action (purchase, teleport, message sending) without the player's
  consent;
* a message that breaks the interface, floods the chat or corrupts the saved data of other users;
* anything that makes the addon send personal data beyond what the README describes.

## What to expect

Reports are reviewed as soon as reasonably possible. A confirmed problem is fixed in a new release;
please wait for it before disclosing the problem publicly.

## Scope

This policy covers the EbonTomeHunter addon and the tools of this repository. The game client, the
Project Ebonhold server, the ProjectEbonhold and EbonholdHub addons and the other third-party
addons are maintained by their own authors: report their problems to them.

# Politique de sécurité

[English](#security-policy) | **Français**

## Versions prises en charge

Les correctifs de sécurité vont dans la dernière release d'EbonTomeHunter. Mets à jour avant de
signaler un problème.

## Signaler une vulnérabilité

Ne signale pas de faille de sécurité dans une issue GitHub publique. Utilise
**Report a vulnerability** dans l'onglet **Security** du dépôt (signalement privé de GitHub).

Indique :

* une description claire du problème ;
* les étapes pour le reproduire (par exemple le message exact envoyé) ;
* son impact possible ;
* la version de l'addon.

N'inclus ni mot de passe, ni nom de compte, ni autre donnée personnelle.

## Ce qui compte comme une vulnérabilité

EbonTomeHunter reçoit des messages d'autres joueurs : des lieux de drop sur un canal de discussion
caché, et des wishlists envoyées par message d'addon. Par exemple :

* un message qui déclenche une action (achat, téléportation, envoi de message) sans l'accord du
  joueur ;
* un message qui casse l'interface, inonde le chat ou abîme les données sauvegardées des autres
  utilisateurs ;
* tout ce qui ferait envoyer par l'addon des données personnelles au-delà de ce que décrit le README.

## À quoi s'attendre

Les signalements sont examinés dès que raisonnablement possible. Un problème confirmé est corrigé
dans une nouvelle release ; attends-la avant de rendre le problème public.

## Périmètre

Cette politique couvre l'addon EbonTomeHunter et les outils de ce dépôt. Le client du jeu, le serveur
Project Ebonhold, les addons ProjectEbonhold et EbonholdHub et les autres addons tiers sont maintenus
par leurs propres auteurs : leurs problèmes se signalent à eux.
